ハッカソンのための小さな Workers ホスティング

Workers のコードを、
自分のサーバーでそのまま。

Kanzume は、Workers 向けに書いたコード（export default { fetch } と wrangler.jsonc）を書き換えずに動かせるセルフホスト環境です。Docker が動く小さなサーバー 1 台に置けて、サンプル・GitHub・GitHub Actions・git push の 4 つの方法でデプロイできます。

ハッカソンで使いやすい理由

無料のサーバー 1 台で動く

512MB RAM / 0.1 CPU 程度の無料プランを想定して、軽さを最優先に作っています。データは R2 などに暗号化してバックアップでき、空の状態で起動しても自動で戻ります。

wrangler の書き方のまま

fetch ハンドラ・KV・R2・静的アセットを wrangler の設定どおりに使えます。あとから wrangler deploy でほかへ移すときも、コードはそのままです。

4 つの方法でデプロイ

サンプル、GitHub の公開リポジトリ、GitHub Actions、Kanzume 上の Git リポジトリへの push から選べます。ほかのサービスのアカウントは要りません。

チームで見られる管理画面

パスキーでログインし、デプロイ履歴・コード・リクエストのログ・KV と R2 の中身を確認できます。チームには招待リンクで、そのサイトだけを任せられます。

始め方

  1. Kanzume を立てる

    Docker で動かします。Railway などの Docker が動くサービスにもそのまま置けます。

    git clone https://github.com/kazukingzz/Kanzume.git
cd Kanzume
docker compose up -d

  2. 管理画面でパスキーを登録する

    /_admin/kanzume を開き、起動ログに出るセットアップトークンで最初のパスキーを登録し、ルートドメインを決めます。

  3. サイトを作ってデプロイする

    サイト名（サブドメイン）を決めてサイトを作り、サンプル・GitHub・GitHub Actions・git push のどれかでデプロイします。

  4. チームを招待する

    サイトごとに招待リンクを作って渡すと、受け取った人はそのサイトだけを扱えるメンバーになります。

詳しい手順は ドキュメント にあります。このページのソースは examples/worker にあります。

対応している機能

fetch ハンドラ○ES Modules 形式。オブジェクトと WorkerEntrypoint の両方
KV○get / put / delete / list、metadata、expirationTtl
R2○get / put / head / delete / list、range、httpMetadata
Static Assets○html_handling / not_found_handling / run_worker_first
nodejs_compat△buffer・crypto・stream・util など。fs や net は使えない
D1・Durable Objects・Cron・Queues×今は対応していません

Worker は 1 台のサーバーの中で動かすので、デプロイできる人（サイトのメンバー）は信頼する前提です。詳しくは リファレンス を見てください。

バックアップと復元

環境変数 KANZUME_BACKUP_URL に S3 互換ストレージ（Cloudflare R2・AWS S3・B2・MinIO）を指定すると、/data の中身を暗号化して保存し、/data が空の状態で起動したときに最新の世代を自動で復元します。復元が終わるまで、リクエストは受け付けません。未設定ならバックアップしません。

設定

KANZUME_BACKUP_URL=s3://<ACCESS_KEY_ID>:<SECRET_ACCESS_KEY>@<ACCOUNT_ID>.r2.cloudflarestorage.com/<BUCKET>[/<PREFIX>]
  • Cloudflare R2 の API トークンは「Object Read & Write」で、対象をそのバケットだけに絞って作ります。エンドポイントは R2 のバケットの設定にある「S3 API」の URL です。
  • 鍵に / + @ などが入るときはパーセントエンコードします。
  • クエリで keep（残す世代数。既定 48）と interval（定期実行の間隔・分。既定 60）を変えられます。AWS 以外の S3 互換ストレージでリージョンが要るときは region も付けます（既定は AWS ならホスト名から、それ以外は auto）。
  • s3+http:// は http のエンドポイント（手元の MinIO など）、file:///path はローカルのディレクトリ（開発用）です。

いつ保存されるか

  • デプロイ・設定の変更・パスキーの登録・リポジトリの作成や削除のあと（30 秒まとめてから）
  • 定期実行（既定 1 時間ごと）。KV / R2 への書き込みや、デプロイしない git push はここで拾います
  • 止まる前（停止のシグナルを受けたとき、数秒の猶予の中で）
  • 管理者設定の「今すぐバックアップ」

変わったファイルだけを送ります（中身ごとに一度だけ保存）。前回から変更がなければ、新しい世代は作りません。パスキーが 1 つも登録されていない（空・作りかけの）状態は保存しません。

保存されるもの

パスキー・ユーザー・トークン・ドメイン、サイト（リリース・設定・環境変数・シークレット）、KV と R2 のデータ、Git リポジトリ、デプロイ履歴とログです。SQLite は一貫したスナップショットを取ってから送ります。データは AES-256-GCM で暗号化し、保存先に平文は残りません。

鍵の入れ替え

暗号化の鍵は SECRET_ACCESS_KEY から導出します。API トークンを作り直して SECRET が変わったら、一度だけ URL に ?previous=<旧 SECRET> を付けて起動してください。鍵が引き継がれ、以後は外して構いません（古い世代もそのまま読めます）。

状態の確認

「管理者設定 > バックアップ」に、保存先・最新の世代・最後の実行の結果・起動時の復元の結果が出ます。ログにも [backup] で始まる行が出ます。認証情報はどこにも表示しません。

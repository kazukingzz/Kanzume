Docker で動かす

リポジトリを取得して、Docker Compose で起動します。データはすべて /data（Compose ではボリューム kanzume-data）に置かれます。

git clone https://github.com/kazukingzz/Kanzume.git
cd Kanzume
docker compose up -d

Compose を使わない場合は次のとおりです。

docker build -t kanzume .
docker run -d -p 8080:8080 -v kanzume-data:/data kanzume

KANZUME_ORIGIN・KANZUME_SETUP_TOKEN・KANZUME_BACKUP_URL・KANZUME_PORT（公開するポート。既定 8080）は、.env か環境変数で渡します。ほかの設定は 環境変数の一覧 を見てください。

最初のパスキーを登録する

  1. https://<あなたのホスト>/_admin/kanzume を開きます。
  2. セットアップトークンを入力します。KANZUME_SETUP_TOKEN を渡していなければ、起動ログ（docker compose logs）に出ています。
  3. ルートドメイン（例: example.com）を確かめて、「パスキーを登録」を押します。

最初にパスキーを登録した人が管理者になります。ほかの人は、管理者が作る 招待リンク から参加します。

ドメインと DNS

サイトは <サイト名>.<ルートドメイン> で配信します。DNS は、ドメイン本体（example.com）とワイルドカード（*.example.com）の両方を Kanzume に向けてください。

  • ルートドメインは「管理者設定 > ドメイン」で変えられます。環境変数 KANZUME_ORIGIN（例: https://example.com）を渡すと、そちらが優先されます。
  • 管理画面は、サイトに使っていないホスト（例: admin.example.com）でも開けます。管理画面を開いているホスト名は、サイトのサブドメインには使えません。
  • パスキーは管理画面を開いたホスト名に結び付きます。ホストを変えると、そのホストでパスキーを登録し直す必要があります。

PaaS で動かすとき

Railway・Render などの Docker が動くサービスにも置けます。ワイルドカードのカスタムドメイン（*.example.com）を設定できるサービスを選んでください。

  • /data に永続ボリュームを付けられるなら付けます。
  • 付けられない（再デプロイでデータが消える）場合は、バックアップ を設定してください。空の /data で起動したときに、最新の状態が自動で戻ります。
  • メモリ 512MB・0.1 CPU 程度でも動くように作っています。

Worker の分離

Worker 付きのサイトは、サイトごとに 1 つの子プロセスで動きます。Kanzume 本体（管理画面・静的アセット・Git・バックアップ）は Worker のコードを動かしません。

  • 子プロセスはサイトごとに別のユーザー（uid 20000〜）で動き、Node の権限モデル（--permission）で、読み書きできるのはそのサイトのディレクトリだけです。child_process・worker_threads は使えません。
  • ほかのサイトの KV・R2・シークレット、Kanzume のセッションやトークン（admin.json）、Kanzume の環境変数（KANZUME_BACKUP_URL など）には届きません。シークレットは起動時に本体から渡します。
  • 子プロセスのヒープは 64 MiB までです。しばらく使われない子は止まり、次のアクセスで起動し直します（KANZUME_WORKER_IDLE_SEC・KANZUME_MAX_WORKERS）。落ちても次のリクエストで起動し直します。
  • 別のユーザーで子を起動するため、Kanzume 本体は root で動きます（Docker イメージの既定）。root でないときは権限モデルだけで守り、起動ログに警告を出します。
  • 静的サイト（Worker のないサイト）は本体が配信し、子プロセスは起動しません。

環境変数

PORT待ち受けるポート（8080）
KANZUME_DATA_DIRデータの置き場所（/data）
KANZUME_ORIGINルートドメインの URL。管理者設定のドメインより優先する
KANZUME_SETUP_TOKEN最初のパスキー登録に使うトークン。未設定なら起動ログに出る
KANZUME_BACKUP_URLバックアップ の保存先
KANZUME_MAX_UPLOAD_MBデプロイ・アップロードの上限（50）
KANZUME_REPO_QUOTA_MBGit リポジトリ 1 つの容量の上限（200）
KANZUME_CPU_TIMEOUT_MSWorker の同期処理の打ち切り時間（5000）
KANZUME_WORKER_IDLE_SEC使われていない Worker の子プロセスを止めるまでの時間（600）
KANZUME_MAX_WORKERS同時に動かす Worker の子プロセスの数（5）
KANZUME_ISOLATIONinline にすると Worker を子プロセスに分けず本体の中で動かす（開発・切り分け用。分離されません）
KANZUME_LOG_RETENTION_HOURSリクエストのログを残す時間（72）
KANZUME_SAMPLES_REPO公開リポジトリからのデプロイで案内するサンプルのリンク先（fork したら自分のリポジトリの https://github.com/<owner>/<repo>/tree/<branch>）

制限

KVキー 512 バイト、値 25 MiB、metadata 1024 バイト、有効期限は 60 秒以上
R2キー 1024 バイト、マルチパートアップロードは不可
環境変数・シークレット値 1 つ 5KB、全体で 64KB
招待リンク1 人 1 回、7 日間
リリース新しいものから 3 つを残す

URL

/_admin/kanzume管理画面（サイトのホストでは管理画面のホストへ移動）
/_api/deployGitHub Actions からのデプロイ（どのホストでも Kanzume が受ける）
/_git/<サイト>.gitサイトの Git リポジトリ
/_healthヘルスチェック

開発

npm install
npm run dev
npm test

Node 24 の型ストリップで TypeScript をそのまま実行します（ビルド不要）。

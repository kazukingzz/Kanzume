デプロイ

サイトの「デプロイ」タブで、5 つの方法から選びます。デプロイ済みのサイトでも、ページの下の「新しくデプロイ」から選べます（今のリリースを置き換えます）。

ファイルから（ドラッグ＆ドロップ）

手元のフォルダ・ファイル・zip を、ドロップするか「ファイルを選ぶ」「フォルダを選ぶ」で選ぶと、デプロイの内容を確かめる画面になります。

  • wrangler の設定（wrangler.jsonc / wrangler.json / wrangler.toml）があるとき: その設定でデプロイします。Worker は GitHub の公開リポジトリと同じく Kanzume の中でバンドルします（npm パッケージは使えないので、ビルドしたものを落とすか GitHub Actions を使ってください）。name は違っていても、そのサイトにデプロイします。
  • ないとき: 全体を静的サイトとして配信します。トップの index.html が / になります。
  • dist/ などのフォルダを丸ごと落としたときは、その中身をトップとして扱います。zip も中のフォルダ 1 つだけなら同じです。
  • .git・node_modules・.DS_Store・__MACOSX は含めません。パスワード付きの zip と ZIP64 形式の zip には対応していません。
  • 大きさの上限は、圧縮した状態で KANZUME_MAX_UPLOAD_MB（50 MB）です。

サンプルから

用意してあるサンプル（このページの examples/worker）を、そのサイトとしてデプロイします。

GitHub の公開リポジトリから

public リポジトリの URL（トップか /tree/<ブランチ>/<ディレクトリ>）を入れて「次へ」を押すと、wrangler の設定の vars を初期値にした環境変数とシークレットの確認画面になります。Kanzume の中でバンドルするので、npm パッケージの import やビルドが必要なものは、次の GitHub Actions を使ってください。

GitHub Actions から

  1. wrangler の設定の name をサイトの ID にします。
  2. 「設定 > トークン」 で個人トークンを発行し、GitHub のリポジトリの Secrets に KANZUME_TOKEN として登録します。
  3. Variables に KANZUME_URL（管理画面の URL。例: https://admin.example.com）を登録します。
  4. 次のワークフローを .github/workflows/deploy.yml に置いて push します。
name: Deploy to Kanzume
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: kazukingzz/Kanzume/action@main
        with:
          url: ${{ vars.KANZUME_URL }}
          token: ${{ secrets.KANZUME_TOKEN }}

Action が wrangler でバンドルし、ビルドに失敗したときもその理由が管理画面のデプロイ履歴に残ります。

サイトのリポジトリから（git push）

サイトの「リポジトリ」タブで「リポジトリを作成」を押すと、Kanzume 上にサイトと同じ名前の Git リポジトリができます。GitHub は要りません。

git remote add origin https://admin.example.com/_git/blog.git
git push -u origin main
  • ユーザー名は何でもよく、パスワードには個人トークンを入力します。
  • デフォルトブランチ（main）への push だけをデプロイします。ほかのブランチは保存だけします。
  • wrangler の name がリポジトリ名と違うコミットはデプロイしません。
  • デフォルトブランチは削除できません。リポジトリの容量には上限があります（KANZUME_REPO_QUOTA_MB）。
  • すでに origin がある（GitHub から clone した）ときは、git remote set-url origin … で付け替えるか、別の名前で追加します。
  • GitHub の URL からのデプロイと同じく Kanzume の中でバンドルするので、npm パッケージが必要なものは Actions を使ってください。

wrangler の設定

wrangler.jsonc・wrangler.json・wrangler.toml のどれかを読みます。使う項目は次のとおりです。

nameサイトの ID（Actions と git push では必須）
mainWorker のエントリ。なければ静的サイト
compatibility_date / compatibility_flagsnodejs_compat で node: のモジュールの一部が使える
assetsdirectory・binding・html_handling・not_found_handling・run_worker_first
vars環境変数（管理画面の値が優先）
kv_namespacesbinding だけを使う（id は無視）
r2_bucketsbinding と bucket_name（英小文字・数字・ハイフンで 2〜63 文字）

サンプルの設定は、そのまま wrangler deploy でも Cloudflare にデプロイできます。

{
  "name": "blog",
  "main": "src/index.ts",
  "compatibility_date": "2026-10-01",
  "compatibility_flags": ["nodejs_compat"],
  "assets": { "directory": "./public", "binding": "ASSETS" },
  "vars": { "GREETING": "hello" },
  "kv_namespaces": [{ "binding": "KV", "id": "x" }],
  "r2_buckets": [{ "binding": "BUCKET", "bucket_name": "blog" }]
}

リリース

新しいリリースは、Worker の読み込みまで成功してから切り替えます。失敗したデプロイは公開中のリリースに影響しません。リリースは新しいものから 3 つまで残します。
